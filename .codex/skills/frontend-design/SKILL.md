# Frontend Design

## Overview

Create distinctive, production-grade frontend interfaces that avoid generic AI aesthetics. Implement real, working code with a clear visual point of view, strong hierarchy, and careful detail.

## Design Thinking

Before coding, define the direction:

- Purpose: What problem does the interface solve, and who uses it?
- Tone: Choose a deliberate direction such as refined minimal, editorial, retro-futurist, playful, industrial, brutalist, organic, or luxury.
- Constraints: Respect framework, performance, responsiveness, and accessibility requirements.
- Differentiation: Identify the one thing the user should remember about the design.

Choose a clear conceptual direction and execute it consistently. Bold maximalism and refined minimalism can both work if the result is intentional.

## Aesthetic Rules

Focus on these areas:

- Typography: Use characterful fonts and strong hierarchy. Avoid generic defaults like Arial, Inter, Roboto, and system-first stacks unless the existing product already depends on them.
- Color: Commit to a cohesive palette. Prefer CSS variables or theme tokens. Let one or two dominant choices define the atmosphere.
- Motion: Use a few meaningful transitions or reveals. In React, prefer the existing project motion stack when available.
- Composition: Favor asymmetry, overlap, depth, controlled whitespace, and layouts that do not look template-generated.
- Visual detail: Add texture, atmosphere, or distinctive framing when it supports the concept.

Avoid generic AI patterns: purple-on-white gradients, interchangeable SaaS card grids, predictable icon rows, and safe default typography.

## Implementation Rules

- Produce working code, not mock snippets.
- Match complexity to the visual direction.
- Preserve the project's existing framework and styling system.
- Keep functionality intact while improving design quality.
- Prefer focused changes over unnecessary rewrites.

## Completion Check

Before finishing, verify:

- The design has a specific visual identity.
- Typography, spacing, and color hierarchy are intentional.
- The UI does not look like a generic scaffold or template.
- The implementation remains production-usable.
- The result fits the product context instead of showcasing random decoration.
